# LLM-асистент

Користувач робить запит у **свою** LLM (ChatGPT, Claude, Gemini) за готовим промптом з його даними, а структуровану відповідь повертає в застосунок. Cookly не платить за LLM і не тримає ключів.

## Сценарії MVP

| Сценарій | Дані в промпті | Повернення |
|---|---|---|
| **Що приготувати** | Запаси, обладнання сім'ї, вподобання й алергії | Рецепт або кілька рецептів у JSON → прев'ю → приватний [рецепт](recipes/recipes.md) |
| **Аналіз раціону** | Облік з'їденого, норми, статистика за період | Лише текст, лишається в LLM-застосунку |

## Сценарій «Що приготувати»

1. Користувач обирає сценарій і провайдера.
2. **Прев'ю даних**: що саме піде в промпт. Чутливе (вага, цілі) за замовчуванням вимкнено, вмикається галочками.
3. Застосунок відкриває LLM з готовим промптом:
   - ChatGPT — `chatgpt.com/?q=…`;
   - Claude — `claude.ai/new?q=…`;
   - Gemini — офіційного параметра немає: промпт копіюється в буфер і відкривається застосунок.
4. LLM відповідає JSON-блоком з маркером `cookly/v1`.
5. Користувач **копіює** відповідь або **ділиться** нею в Cookly (share extension).
6. Застосунок знаходить блок у буфері, валідує за схемою і показує **прев'ю**: рядки зіставлені з каталогом інгредієнтів, незіставлені — на вибір.
7. Користувач підтверджує або замінює інгредієнти і зберігає приватний рецепт.

## Шаблони промптів

- Зберігаються в [адмінці](admin.md) з **версіями**: сценарій, текст з плейсхолдерами даних, схема відповіді, провайдери.
- Доступність шаблону керується [фіча-прапорцями](feature-flags.md): промпт можна поправити або вимкнути без релізу застосунку.
- Дані стискаються, бо довжина URL обмежена; якщо промпт задовгий — запасний шлях через буфер.

## Рішення

- LLM користувача, а не наша. *Чому*: нуль витрат на інференс і жодних ключів; користувач уже має підписку.
- Повернення через копіювання чи share. *Чому*: споживчі LLM-застосунки не вміють робити POST на наш ендпоінт, а токен доступу в промпті — діра в безпеці. *Відкинуто*: посилання з даними від LLM — LLM погано кодують base64, і довжина обмежена; Custom GPT чи MCP — значно складніше, див. [майбутнє](future.md).
- Схема з версією й прев'ю. *Чому*: відповідь LLM може бути неповною чи помилковою, а в базу потрапляє лише підтверджене.
- Нічого не відправляється без прев'ю даних. *Чому*: дані йдуть стороннім сервісам з вибору користувача.

## Граничні випадки

- JSON зламаний чи неповний → застосунок показує, що вдалося розібрати, і пропонує повторити запит.
- Схема старої версії шаблону → клієнт підтримує попередню версію схеми, поки шаблон не оновлено.
- Інгредієнта з відповіді немає в каталозі → користувач обирає найближчий або створює продукт ([модерація](catalog/moderation.md)).
