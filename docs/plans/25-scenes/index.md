# B25 · Сцени

Опис і доставка сцен кухні: формат, синхронізація з репозиторію, асети, місця зберігання, запропоновані продукти й мапінг категорій. Новий предмет на кухні не вимагає релізу застосунку. Клієнт — у [сценах кухні M2](../m02-sign-in-and-onboarding/kitchen-scenes.md).

Критерії приймання — у [юзер-сторі](user-stories.md).

## Обсяг

- Формат опису сцени, `formatVersion`, слоти полиць, переходи.
- `api scenes sync`, асети в Garage, маніфест і API.
- Сцена обладнання з довідника `equipment`.
- Місця зберігання, запропоновані продукти, мапінг вузол категорії → місце.
- Запасні спрайти.

**Не входить**: рушій на Skia і легкий режим ([M2](../m02-sign-in-and-onboarding/kitchen-scenes.md)), поля сцени в довіднику ([B6](../06-catalog/directories.md#обладнання)), поле `storageLocation` ([B13](../13-pantry/model.md#місце-зберігання)), екрани адмінки ([A12](../../roadmap.md#адмінка)), візуальний редактор сцен ([майбутнє](../../future.md)).

## Ключові рішення

| Рішення | Відкинуто | Чому |
|---|---|---|
| Опис у репозиторії, `scenes sync` під час деплою | Редагування в адмінці | Позиції предметів — робота дизайнера, а не оператора; зміни проходять рев'ю |
| `formatVersion` → легкий режим у старого клієнта | Малювати як вийде | Застосунок не падає на незнайомому форматі |
| Асети з хешем в імені | Сталі імена | Кешуються назавжди, оновлення без конфліктів |
| Сцена обладнання збирається з таблиці | Окремий опис | Новий рядок довідника одразу на сцені |
| Слоти полиць, клієнт розставляє сам | Точні позиції продуктів | Продуктів багато й вони міняються; вручну це ніхто не підтримає |
| Запропоновані продукти й мапінг — у БД | У репозиторії | Модератор змінює їх без деплою |
| API не залежить від `scene.skia` | Вимикати разом із прапорцем | Легкому режиму потрібні ті самі місця й продукти |
