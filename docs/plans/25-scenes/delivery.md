# Доставка

Як сцени потрапляють з репозиторію на пристрій.

## Синхронізація

- Описи й PNG лежать у репозиторії в теці `scenes/`.
- **`api scenes sync`** запускається під час деплою, як [`i18n sync`](../04-i18n/ui-strings.md#цикл-ключів):
  - перевіряє опис за схемою: унікальні `id`, координати 0–1, наявні асети й підсцени → інакше деплой падає;
  - завантажує асети в Garage під **іменами з хешем вмісту**;
  - оновлює сцени в БД;
  - збільшує `version`, якщо вміст змінився.
- Сцена, якої більше немає в репозиторії, позначається `retired` і не повертається клієнтам.

## Асети

- Публічний бакет ([B10](../10-media/uploads.md)), URL з хешем, кеш **назавжди**.
- Формат — PNG; піксельний стиль і палітра [B10](../10-media/pixel-art.md).
- **Бюджет** — до **5 МБ** на всі сцени разом; CI падає на перевищенні.

## API

Вимагає access-токен.

| Метод і шлях | Що робить |
|---|---|
| `GET /v1/scenes` | Маніфест: ключі, версії, `formatVersion`, хеші, сумарний розмір; з `ETag` |
| `GET /v1/scenes/{key}` | Опис сцени з абсолютними URL асетів |

- Невідома чи `retired` сцена → `404 scene.not_found`.
- Прапорець `scene.skia` ([B20](../20-feature-flags/flags.md)) на API **не впливає**: він перемикає лише клієнт.

## Клієнт

- Завантажує сцену під час відкриття і решту — **у фоні** після онбордингу.
- Перевіряє маніфест через `ETag` на старті; завантажує лише сцени зі зміненим хешем.
- Без мережі — з кешу; кешу немає → [легкий режим](../m02-sign-in-and-onboarding/kitchen-scenes.md#легкий-режим).
