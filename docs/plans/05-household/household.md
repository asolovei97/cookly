# Сім'я

Сутність сім'ї, онбординг, права й видимість, вихід і передача ролі.

## Поля

- Назва.
- **Місто** — необов'язкове, з довідника `cities`.
- Країна й валюта: `UA` / `UAH` за замовчуванням.
- **Таймзона** (IANA) — за замовчуванням таймзона `owner`; для персон без акаунта й задач воркера ([B17](../17-nutrition-log/days.md#таймзони)). Акаунт має власну таймзону, автоматично з пристрою.

## Місто

- На онбордингу **не питаємо**.
- Місто сім'ї — лише **значення за замовчуванням**: для відображення цін і як підказка під час запису ціни. Кожне спостереження ціни має власне місто, див. [B8](../08-prices/observations.md#місто-й-геолокація).
- Застосунок пропонує вказати місто за контекстом (вибір в один тап), наприклад коли користувач уперше відкриває порівняння цін.
- Поки міста немає, ціни рахуються за **медіаною по Україні**.
- Довідник `cities` — початковий список міст України; редагування з адмінки — у B6 / A3.

## Онбординг

1. Після реєстрації акаунт має `householdId: null` ([B2](../02-app-auth/flows.md#реєстрація)).
2. Користувач або створює сім'ю, або приєднується за [кодом запрошення](invites.md).
3. Створення сім'ї створює й **персону акаунта**: ім'я — з `displayName`, рік народження — з реєстрації, решту полів ([персона](persons-and-goals.md#поля-персони)) користувач вводить. Акаунт стає `owner`.
4. Далі `owner` додає інші персони.

## Ендпоінти

| Метод і шлях | Хто | Що робить |
|---|---|---|
| `POST /v1/household` | акаунт без сім'ї | Створити сім'ю з персоною акаунта |
| `GET /v1/household` | учасник | Сім'я, персони, ролі |
| `PATCH /v1/household` | `owner` | Назва, місто |
| `POST /v1/household/leave` | учасник | Вийти з сім'ї |
| `POST /v1/household/owner` | `owner` | Передати роль іншому учаснику з акаунтом |
| `POST /v1/household/persons` | учасник | Додати персону без акаунта |
| `PATCH /v1/household/persons/{id}` | див. права | Змінити персону |
| `DELETE /v1/household/persons/{id}` | `owner` | Архівувати персону без акаунта або видалити учасника |
| `GET`/`POST /v1/household/persons/{id}/weights` | див. видимість | Історія ваги, новий запис |
| `PUT`/`DELETE /v1/household/persons/{id}/norm-override` | див. права | Ручна норма; скинути |
| `POST`/`DELETE /v1/household/persons/{id}/invite` | `owner` | Створити чи відкликати код |
| `POST /v1/household/join` | акаунт без сім'ї | Приєднатися за кодом |
| `GET /v1/cities?q=` | будь-хто з токеном | Пошук міста |

## Права

| Дія | Хто може |
|---|---|
| Редагувати персону з акаунтом | Лише сам цей акаунт |
| Редагувати персону без акаунта | Будь-хто з сім'ї |
| Змінювати сім'ю (назву, місто) | `owner` |
| Додавати й видаляти персони, керувати кодами | `owner` |

Порушення → `403 household.forbidden`.

## Видимість

- Імена, цілі й норми всіх персон бачить уся сім'я — вони потрібні для планування порцій.
- **Вагу й історію ваги персони з акаунтом** бачить лише вона сама. Іншим учасникам ці поля не повертаються.
- Вагу персон без акаунта бачать усі учасники.

## Вихід, видалення, передача ролі

- **`member` виходить** або **`owner` його видаляє**: персона лишається в сім'ї як персона без акаунта (з історією), а акаунт отримує `householdId: null`. Активний код запрошення для такої персони можна створити знову.
- **Персону без акаунта видаляє `owner`**: вона архівується (м'яке видалення) і зникає зі складу, але посилання на неї лишаються чинними.
- **Передача ролі `owner`** — лише іншому учаснику з акаунтом; попередній `owner` стає `member`.
- **`owner` хоче вийти**:
  - є інші учасники з акаунтами → `409 household.owner_must_transfer`;
  - він єдиний акаунт → сім'я видаляється разом з персонами.
