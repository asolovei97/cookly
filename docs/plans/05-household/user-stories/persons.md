# Юзер-сторі — персони

US-HH-6…10. Загальні правила — в [індексі юзер-сторі](index.md).

## US-HH-6 — Персони
Як власник сім'ї, я хочу додати всіх, на кого готую.

**AC-6.1 (Додавання персони):**
- Given `owner`,
- When він додає персону з ім'ям, статтю, роком народження, зростом, вагою, активністю й ціллю,
- Then персона створюється без акаунта, з першим записом ваги і розрахованою нормою.

**AC-6.2 (Некоректні дані):**
- Given зріст, вага чи рік народження поза допустимими межами контракту,
- When `owner` додає персону,
- Then повертається `422` з `request.invalid` і `errors[]` для відповідних полів.

## US-HH-7 — Норма
Як користувач, я хочу отримати безпечну норму калорій і БЖВ під свою ціль.

**AC-7.1 (Розрахунок):**
- Given дорослий чоловік 30 років, 180 см, 80 кг, помірна активність, ціль `maintain`,
- When норма розраховується,
- Then калорії дорівнюють `(10×80 + 6,25×180 − 5×30 + 5) × 1,55`, білок — `1,4 × 80` г, жири — у межах 25–30% калорій, вуглеводи — решта.

**AC-7.2 (Межа дефіциту):**
- Given ціль `lose` з темпом, що дає дефіцит понад 25% TDEE або норму нижчу за BMR,
- When норма розраховується,
- Then норма обрізається до межі, і у відповіді є `normCapped: true`.

**AC-7.3 (Перерахунок):**
- Given персона без ручного перевизначення,
- When додається новий запис ваги або змінюється активність,
- Then норма перераховується.

**AC-7.4 (Ручне перевизначення):**
- Given персона з ручною нормою,
- When додається новий запис ваги,
- Then норма не змінюється; після `DELETE …/norm-override` повертається розрахована норма.

## US-HH-8 — Діти
Як батько, я хочу планувати харчування дитини без небезпечних цілей.

**AC-8.1 (Ціль для дитини):**
- Given персона до 18 років,
- When для неї задають ціль `lose` чи `gain`,
- Then повертається `422` з кодом `household.goal_not_allowed`.

**AC-8.2 (Норма дитини):**
- Given персона до 18 років з ціллю `maintain`,
- When норма розраховується,
- Then калорії беруться з довідкової таблиці EFSA за віком і статтю.

## US-HH-9 — Історія ваги
Як користувач, я хочу записувати вагу, щоб бачити прогрес.

**AC-9.1 (Новий запис):**
- Given персона,
- When її власник-акаунт додає запис ваги,
- Then запис зберігається, і поточна вага персони дорівнює йому.

**AC-9.2 (Запис іншим учасником):**
- Given персона з акаунтом A,
- When інший учасник намагається додати їй запис ваги,
- Then повертається `403` з кодом `household.forbidden`.

## US-HH-10 — Запрошення
Як власник, я хочу запросити людину, для якої вже створив персону.

**AC-10.1 (Створення коду):**
- Given персона без акаунта,
- When `owner` створює код,
- Then повертається код формату `COOK-XXXXXX`, що діє 7 днів, а попередній код цієї персони відкликається.

**AC-10.2 (Приєднання):**
- Given акаунт без сім'ї і чинний код,
- When він надсилає `POST /v1/household/join`,
- Then акаунт прив'язується до персони як `member`, рік народження персони замінюється роком з акаунта, решта полів лишається, а код стає використаним.

**AC-10.3 (Недійсний код):**
- Given код невідомий, прострочений, відкликаний чи використаний,
- When акаунт надсилає його,
- Then повертається `404` з кодом `household.invite_invalid`.

**AC-10.4 (Уже в сім'ї):**
- Given акаунт уже в сім'ї,
- When він надсилає чинний код,
- Then повертається `409` з кодом `household.already_member`.

**AC-10.5 (Підбір кодів):**
- Given акаунт надіслав 10 спроб за хвилину,
- When він надсилає ще одну,
- Then повертається `429` з кодом `household.rate_limited` і `Retry-After`.

**AC-10.6 (Персона з акаунтом):**
- Given персона вже має акаунт,
- When `owner` створює для неї код,
- Then повертається `409` з кодом `household.person_has_account`.
