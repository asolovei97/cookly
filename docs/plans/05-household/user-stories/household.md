# Юзер-сторі — сім'я

US-HH-1…5. Загальні правила — в [індексі юзер-сторі](index.md).

## US-HH-1 — Створення сім'ї
Як новий користувач, я хочу створити сім'ю і свою персону, щоб почати планувати.

**AC-1.1 (Створення):**
- Given акаунт з `householdId: null`,
- When він надсилає `POST /v1/household` з назвою і полями своєї персони без міста,
- Then створюються сім'я з `UA` / `UAH` і без міста, персона акаунта з ім'ям з `displayName` і роком народження з реєстрації, акаунт стає `owner`, і `GET /v1/me` повертає `householdId`.

**AC-1.2 (Уже в сім'ї):**
- Given акаунт уже належить до сім'ї,
- When він надсилає `POST /v1/household`,
- Then повертається `409` з кодом `household.already_member`.

## US-HH-2 — Місто
Як користувач, я хочу вказати місто, коли воно знадобиться для цін.

**AC-2.1 (Пошук міста):**
- Given у довіднику є «Київ»,
- When клієнт викликає `GET /v1/cities?q=киї`,
- Then «Київ» є в результатах.

**AC-2.2 (Встановлення міста):**
- Given `owner` і сім'я без міста,
- When він надсилає `PATCH /v1/household` з id міста,
- Then місто зберігається.

**AC-2.3 (Невідоме місто):**
- Given id міста не існує,
- When `owner` надсилає його,
- Then повертається `422` з `errors[]` для `/cityId`.

## US-HH-3 — Права в сім'ї
Як учасник, я хочу, щоб мою персону не змінював хтось інший, а дітей могли вести всі.

**AC-3.1 (Своя персона):**
- Given `member` з акаунтом,
- When він змінює свою персону,
- Then зміни зберігаються.

**AC-3.2 (Чужа персона з акаунтом):**
- Given персона іншого учасника з акаунтом,
- When `owner` чи `member` намагається її змінити,
- Then повертається `403` з кодом `household.forbidden`.

**AC-3.3 (Персона без акаунта):**
- Given персона без акаунта,
- When `member` змінює її,
- Then зміни зберігаються.

**AC-3.4 (Дії власника):**
- Given `member`,
- When він змінює назву сім'ї, додає персону чи створює код запрошення,
- Then повертається `403` з кодом `household.forbidden`.

## US-HH-4 — Видимість ваги
Як учасник, я хочу, щоб мою вагу бачив лише я.

**AC-4.1 (Склад сім'ї):**
- Given у сім'ї персона з акаунтом A і персона без акаунта,
- When інший учасник викликає `GET /v1/household`,
- Then він бачить імена, цілі й норми обох персон, вагу персони без акаунта, але не вагу персони A.

**AC-4.2 (Історія ваги):**
- Given персона з акаунтом A,
- When інший учасник запитує її історію ваги,
- Then повертається `403` з кодом `household.forbidden`.

## US-HH-5 — Вихід і передача ролі
Як учасник, я хочу вийти з сім'ї, не ламаючи її історію.

**AC-5.1 (Вихід учасника):**
- Given `member` з персоною,
- When він викликає `POST /v1/household/leave`,
- Then акаунт отримує `householdId: null`, а персона лишається в сім'ї як персона без акаунта.

**AC-5.2 (Видалення учасника):**
- Given `owner` і `member` з акаунтом,
- When `owner` видаляє персону цього учасника,
- Then результат такий самий, як в AC-5.1.

**AC-5.3 (Архівування персони без акаунта):**
- Given персона без акаунта,
- When `owner` її видаляє,
- Then персона зникає зі складу сім'ї, але запис лишається архівованим.

**AC-5.4 (Передача ролі):**
- Given `owner` і `member` з акаунтом,
- When `owner` передає йому роль,
- Then `member` стає `owner`, а попередній `owner` — `member`.

**AC-5.5 (Передача персоні без акаунта):**
- Given персона без акаунта,
- When `owner` намагається передати їй роль,
- Then повертається `422` з `errors[]` для `/personId`.

**AC-5.6 (Власник виходить, є інші акаунти):**
- Given `owner` і ще один учасник з акаунтом,
- When `owner` викликає вихід,
- Then повертається `409` з кодом `household.owner_must_transfer`.

**AC-5.7 (Власник — єдиний акаунт):**
- Given `owner` — єдиний акаунт у сім'ї з персонами без акаунта,
- When він виходить,
- Then сім'я і її персони видаляються, а акаунт отримує `householdId: null`.
