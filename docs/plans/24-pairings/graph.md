# Граф

Ребра поєднань, їхні сили, звідки вони беруться і хто їх змінює.

## Ребро

| Поле | Примітка |
|---|---|
| Бік A, бік B | Інгредієнт або вузол [дерева категорій](../06-catalog/categories.md) |
| Сила | `classic` · `strong` · `good` · `avoid` |
| Джерело | `moderator` або `seed:<датасет>` |
| Нотатка | Необов'язкова, для модераторів |

- Пара **невпорядкована**: `(A, B)` і `(B, A)` — одне ребро.
- **Одне ребро на пару** → друге з тією самою парою `409 pairing.duplicate_edge`.
- Ребро з самим собою → `422 pairing.self_edge`.

## Ваги

| Сила | Вага за замовчуванням |
|---|---|
| `classic` | 3 |
| `strong` | 2 |
| `good` | 1 |
| `avoid` | −3 |

Ваги — параметри конфігу.

## Успадкування

- Ребро на **вузол категорії** діє на всі інгредієнти його гілки — те саме правило гілки, що й для [алергій](../12-meal-plan/preferences.md).
- Для пари інгредієнтів береться **найконкретніше** ребро: інгредієнт > вузол нижче > вузол вище.
- Ребра немає ні на якому рівні → пара **нейтральна**.

## Стартовий імпорт

- **Офлайн-скрипт** (команда воркера), запускається лише після перевірки ліцензій датасетів (Flavor Network, FlavorDB).
- Назви датасету зіставляються з інгредієнтами каталогу; незіставлене пропускається зі звітом.
- Імпортовані ребра **одразу активні**, але **не сильніші за `good`**; джерело `seed:<датасет>`.
- `classic` і `strong` ставить лише модератор.
- Повторний імпорт не перезаписує ребер, які змінив модератор.

## Об'єднання інгредієнтів

Під час об'єднання X → Y ([B7](../07-moderation/merge.md#обєднання-x--y)):

- ребра X переносяться на Y;
- якщо в Y уже є ребро з тим самим сусідом — лишається **сильніше**, а `avoid` перемагає завжди;
- ребро X ↔ Y зникає.

## Кеш

- Ребра в PostgreSQL; кожен інстанс тримає граф **у пам'яті** з версією.
- Зміна збільшує версію і розсилається через **Redis pub/sub**, як прапорці ([B20](../20-feature-flags/enforcement.md#кеш-і-версія)).

## Модерація

- Ребра додає, змінює й видаляє `moderator` (право «довідники», [B3](../03-admin-auth/access.md#ролі-й-права)).
- Зміни пишуться в [аудит](../03-admin-auth/audit-and-users.md).
- Модератор бачить агрегати 👍 / 👎 ([підказки](hints.md#-і-)).

## Адмін-ендпоінти

| Метод і шлях | Що робить |
|---|---|
| `GET /admin/v1/pairings?node=` | Ребра вузла чи інгредієнта, зокрема успадковані |
| `POST`/`PATCH`/`DELETE /admin/v1/pairings/{id}` | Ребро |
| `GET /admin/v1/pairings/feedback` | Найбільше 👎; пари без ребра з багатьма 👍 |

## Прапорець

`pairings` (`optional`): вимикає підказки й ендпоінти застосунку ([B20](../20-feature-flags/enforcement.md#x-feature)). Без нього «з того, що є» сортує лише за покриттям.
