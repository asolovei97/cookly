# Юзер-сторі — граф

US-PAIR-1…3. Загальні правила — в [індексі юзер-сторі](index.md).

## US-PAIR-1 — Ребра й успадкування
Як модератор, я хочу одним ребром описати «ягоди пасують до вершків».

**AC-1.1 (Категорія):**
- Given ребро «Ягоди» ↔ «Вершки» `strong`,
- When читається пара «Полуниця» ↔ «Вершки 33%»,
- Then вага 2.

**AC-1.2 (Конкретніше перемагає):**
- Given ребро «Ягоди» ↔ «Вершки» `strong` і «Журавлина» ↔ «Вершки» `avoid`,
- When читається пара «Журавлина» ↔ «Вершки 33%»,
- Then вага −3.

**AC-1.3 (Невпорядкована пара):**
- Given ребро «Томат» ↔ «Базилік»,
- When створюють «Базилік» ↔ «Томат»,
- Then `409 pairing.duplicate_edge`.

## US-PAIR-2 — Імпорт і об'єднання
Як модератор, я хочу стартовий граф без ризику зіпсувати свої правки.

**AC-2.1 (Межа сили):**
- Given датасет дає парі найвищий збіг,
- When виконується імпорт,
- Then ребро `good` з джерелом `seed:<датасет>`.

**AC-2.2 (Правки модератора):**
- Given модератор змінив імпортоване ребро на `classic`,
- When імпорт виконують знову,
- Then ребро лишається `classic`.

**AC-2.3 (Об'єднання):**
- Given X ↔ «Часник» `good`, Y ↔ «Часник» `strong`, X ↔ «Кріп» `avoid`, Y ↔ «Кріп» `good`,
- When X об'єднують у Y,
- Then Y ↔ «Часник» `strong`, Y ↔ «Кріп» `avoid`.

## US-PAIR-3 — Модерація й 👍 / 👎
Як модератор, я хочу знати, які підказки людям не подобаються.

**AC-3.1 (Одна оцінка):**
- Given користувач поставив 👍 підказці «Курка → Рис»,
- When він ставить 👎 тій самій підказці,
- Then у нього одна оцінка 👎.

**AC-3.2 (Граф не змінюється):**
- Given підказка має 50 👎,
- When читається граф,
- Then ребро не змінилося, а `GET /admin/v1/pairings/feedback` показує підказку серед найгірших.

**AC-3.3 (Права):**
- Given адмін лише з роллю `translator`,
- When він змінює ребро,
- Then `403 admin.forbidden`.
