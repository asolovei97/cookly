# Страва

Результат готування: вага, знімок КБЖВ, списання, залишок, виправлення.

## Вага

- **Зважування** (`cooking.weigh`): для кожної посудини — брутто мінус тара. Тара — з [обладнання сім'ї](../06-catalog/directories.md#обладнання) або введена вручну.
- **Кілька посудин** (дві каструлі) — ваги складаються.
- **Без зважування**: вага = сума інгредієнтів × [коефіцієнт виходу](../09-recipes/composition.md#типовий-вихід) рецепта.

## Знімок КБЖВ

- **Загалом**: Σ кількість × нутрієнти рядка:
  - товар — власні нутрієнти, інакше нутрієнти інгредієнта;
  - інгредієнт — типові нутрієнти;
  - напівфабрикат — знімок його страви на 100 г або `recipe_nutrition`.
- **На 100 г**: загальні / вага × 100.
- **На порцію**: загальні / порції.
- **Вартість страви**: Σ рядків за ціною закупки, з якої їх взяли (товар — ціна останньої закупки, `gift` — 0, невідомо → `partial`). Потрібна для [списань](../18-budget-and-stats/waste.md#вартість) і вартості порції.
- Знімок **незмінний** (крім виправлення нижче) і зберігає фактичний склад: що саме, скільки, з якими нутрієнтами. Зміни каталогу чи рецепта його не змінюють ([B7](../07-moderation/merge.md#знімки-в-історії)).

## Завершення

`cooking.complete`:

1. Рахується вага і знімок; створюється **страва** з **залишком** = вага.
2. Запаси списуються **одним пакетом дельт** за [правилами B13](../13-pantry/usage.md#списання): конкретний товар, інакше рядок інгредієнта, далі товари з найбільшим залишком. Розбіжності повертаються як підказки.
3. Страви-напівфабрикати, використані в рядках, зменшують свій залишок.
4. Якщо сесію почали з запланованого готування — воно отримує **фактичну дату**, і попередження плану перераховуються ([B12](../12-meal-plan/calculations.md#фактична-дата-готування)).

## Виправлення

- Протягом **48 годин** після завершення (`cooking.edit`): змінити кількості, товари, вагу.
- Знімок перераховується; запаси коригуються **компенсуючими дельтами** (різниця між старим і новим складом).
- Записи з'їденого посилаються на страву і грами, тож їхні КБЖВ оновлюються автоматично ([B17](../../roadmap.md#бекенд)).
- Після 48 годин → `rejected` з `cooking.edit_window_closed`.

## Готові страви

- Страва із залишком показується в [запасах](../13-pantry/index.md) у розділі **«Готові страви»**: залишок, строк придатності (дата готування + строк зберігання рецепта).
- Залишок зменшується, коли страву їдять ([B17](../../roadmap.md#бекенд)) або використовують як напівфабрикат.
- ~~«Доїли» чи «викинули» — залишок = 0, причина пишеться в історію.~~ → «Доїли» — залишок = 0. **Викинути** можна частину або все: грами й причина `spoiled` / `given_away` / `other`; запис іде в [журнал списань B18](../18-budget-and-stats/waste.md) з часткою вартості страви.
- Страва зі строком, що минув, лишається з позначкою «строк минув».

## Страва без рецепта

- Готова їжа, яку не готували в застосунку (подарований торт): страва з джерелом `manual`, без сесії й рецепта.
- Поля: назва, вага (= залишок), КБЖВ на 100 г — з аналога (інгредієнт, товар, `recipe_nutrition` рецепта) або вручну, фото необов'язкове.
- Запаси **не списуються**; вартість — 0 грн для `gift`, інакше невідома.
- Далі поводиться як звичайна готова страва: залишок, строк придатності (вводиться вручну, необов'язково), «доїли» чи «викинули».

## Підказка коефіцієнта виходу

- Для **приватного** рецепта сім'ї, який **зважили** щонайменше 3 рази: виміряний вихід кожного разу = вага / сума інгредієнтів.
- Якщо медіана відрізняється від поточного коефіцієнта більше ніж на 5%, рецепт показує підказку «оновити коефіцієнт до X».
- Для адмінських і публічних рецептів підказки немає.

## Фото

- `cooking.photo.attach` з `mediaId` з `uploadMedia` ([B10](../10-media/uploads.md#процес)), мета `cooking_photo`.
- Офлайн фото чекає в черзі клієнта, доки не завершиться завантаження; операція відправляється після цього.
- Фото приготувань ніколи не стають публічними.
