# Юзер-сторі — модерація

Критерії приймання для [плану модерації](index.md). AC перевіряються на рівні API. Кожен AC покривається тестом з назвою `TestAC_<US>_<N>_...`.

## US-MOD-1 — Подання
Як користувач, я хочу поділитися продуктом з усіма, але не всім підряд.

**AC-1.1 (Прапорець під час створення):**
- Given користувач створює товар з `shareWithAll: true`,
- When товар зберігається,
- Then він має `status: pending` і з'являється в черзі; з `shareWithAll: false` — `status: private`.

**AC-1.2 (Подання пізніше):**
- Given приватний товар,
- When користувач викликає `POST /v1/catalog/products/{id}/submit`,
- Then статус стає `pending`.

**AC-1.3 (Ліміт):**
- Given сім'я подала 20 продуктів за добу,
- When вона подає ще один,
- Then повертається `429` з кодом `moderation.rate_limited`.

**AC-1.4 (Повторне подання без змін):**
- Given відхилений товар, який після відхилення не змінювали,
- When користувач подає його знову,
- Then повертається `409` з кодом `moderation.unchanged`.

## US-MOD-2 — Черга
Як модератор, я хочу розбирати подання по черзі і не дублювати роботу колег.

**AC-2.1 (Порядок і фільтр):**
- Given подання різних типів і часу,
- When модератор відкриває чергу з `type=product`,
- Then бачить лише товари, від найстаріших.

**AC-2.2 (М'яке блокування):**
- Given модератор A відкрив картку,
- When модератор B відкриває чергу протягом 15 хвилин,
- Then картка позначена «у роботі в A», але B може її відкрити й діяти.

**AC-2.3 (Без права):**
- Given адмін лише з роллю `translator`,
- When він відкриває чергу,
- Then повертається `403` з кодом `admin.forbidden`.

## US-MOD-3 — Схвалення
Як модератор, я хочу опублікувати перевірений продукт, за потреби виправивши його.

**AC-3.1 (Публічна копія):**
- Given товар сім'ї A на модерації,
- When модератор схвалює його з правкою назви `en`,
- Then створюється публічна копія з правкою, оригінал отримує `publicVersionId` і `status: public`, лишається в сім'ї A, а в аудиті з'являється запис.

**AC-3.2 (Застаріла версія):**
- Given автор змінив товар після того, як модератор відкрив картку,
- When модератор схвалює зі старою версією,
- Then повертається `409` з кодом `moderation.stale`, і нічого не публікується.

## US-MOD-4 — Відхилення
Як автор, я хочу знати, чому мій продукт не прийняли.

**AC-4.1 (Причина):**
- Given товар на модерації,
- When модератор відхиляє його з причиною `incorrect_data` і коментарем,
- Then товар має `status: rejected`, лишається приватним, а автор бачить причину й коментар на картці й у `GET /v1/moderation/my`.

## US-MOD-5 — Пропозиції оновлення
Як автор, я хочу оновлювати опублікований продукт, не ламаючи його для інших.

**AC-5.1 (Пропозиція):**
- Given оригінал з публічною версією,
- When автор змінює опис з `proposeToPublic: true`,
- Then оригінал оновлюється одразу, а в черзі з'являється пропозиція з різницею до публічної версії.

**AC-5.2 (Без пропозиції):**
- Given оригінал з публічною версією,
- When автор зберігає зміни з `proposeToPublic: false`,
- Then змінюється лише оригінал, пропозиції немає.

**AC-5.3 (До схвалення):**
- Given пропозиція на модерації,
- When інша сім'я відкриває публічну версію,
- Then бачить останню схвалену версію; після схвалення — нову.

**AC-5.4 (Заміна пропозиції):**
- Given нерозглянута пропозиція,
- When автор надсилає нову,
- Then у черзі лишається лише нова.

## US-MOD-6 — Сім'я автора
Як автор, я не хочу бачити в пошуку двох однакових продуктів.

**AC-6.1 (Лише оригінал):**
- Given оригінал з публічною версією,
- When сім'я автора шукає продукт за назвою,
- Then повертається оригінал, а публічна копія — ні; інша сім'я бачить публічну копію.

## US-MOD-7 — Об'єднання
Як модератор, я хочу звести дублікати в один запис, не ламаючи історію.

**AC-7.1 (Перенаправлення):**
- Given дублікат X і публічний Y,
- When модератор об'єднує X з Y,
- Then X архівується з `mergedInto: Y`, а `GET` за id X повертає Y.

**AC-7.2 (Активні посилання):**
- Given запас сім'ї посилається на X,
- When задача воркера після об'єднання завершується,
- Then запас посилається на Y.

**AC-7.3 (Історія):**
- Given страва, приготована з X до об'єднання,
- When X об'єднують з Y з іншими нутрієнтами,
- Then КБЖВ страви не змінюються.

**AC-7.4 (Несумісні одиниці):**
- Given інгредієнт X у `g` і Y у `ml`,
- When модератор намагається їх об'єднати,
- Then повертається `422` з кодом `moderation.merge_incompatible`.

**AC-7.5 (Публічна копія):**
- Given оригінал автора з публічною копією C,
- When модератор об'єднує C з Y,
- Then оригінал отримує `publicVersionId: Y`.

## US-MOD-8 — Кандидати в дублікати
Як модератор, я хочу одразу бачити схожі продукти.

**AC-8.1 (Штрихкод і назва):**
- Given публічний товар зі штрихкодом X і публічний товар «Молоко Галичина 2,5%» у категорії «молочні»,
- When модератор відкриває подання з тим самим штрихкодом чи назвою «Молоко Галичина 2.5%» у тій самій категорії,
- Then картка показує відповідний товар серед кандидатів.
