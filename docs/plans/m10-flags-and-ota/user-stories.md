# Юзер-сторі — прапорці й OTA

Критерії приймання для [плану M10](index.md). AC перевіряються RNTL / Jest і Maestro на варіанті `testing`; OTA — на `staging`. Кожен AC покривається тестом з назвою `AC_<US>_<N>_...`.

## US-MFLAG-1 — Прапорці
Як користувач, я бачу лише доступні мені фічі.

**AC-1.1 (Прихована дія):**
- Given `receipts` off,
- When відкривається старт закупки,
- Then шляху «З чека» немає.

**AC-1.2 (Офлайн):**
- Given набір закешовано, немає мережі,
- When застосунок перезапускають,
- Then діє кешований набір.

**AC-1.3 (Значення за замовчуванням):**
- Given кешу немає, немає мережі,
- When читається `core`-ключ і `optional`-ключ,
- Then перший увімкнено, другий вимкнено.

**AC-1.4 (Зміна версії):**
- Given кеш версії 41, відповідь API з `X-Features-Version: 42`,
- When приходить відповідь,
- Then набір перечитано.

**AC-1.5 (Генерація):**
- Given у реєстрі бекенду новий ключ,
- When виконується `make gen`,
- Then ключ у TS-реєстрі; CI падає, якщо згенероване застаріло.

## US-MFLAG-2 — Недоступна фіча
Як користувач, я розумію, чому щось не працює.

**AC-2.1 (403):**
- Given застарілий набір і `403 feature.disabled`,
- When відкривається екран,
- Then «Ця функція зараз недоступна», набір оновлено.

**AC-2.2 (Лише ця фіча):**
- Given `426 feature.upgrade_required` для закупки,
- When відкривається закупка,
- Then заглушка; план меню працює.

**AC-2.3 (Спершу OTA):**
- Given заглушка і доступне OTA,
- When «Оновити»,
- Then оновлення завантажено й застосовано без стора.

**AC-2.4 (Стор):**
- Given заглушка і немає OTA,
- When «Оновити»,
- Then перехід у стор.

## US-MFLAG-3 — Черга операцій
Як користувач, я не хочу втратити дані через вимкнену фічу.

**AC-3.1 (Чекає):**
- Given операція `rejected` з `feature.upgrade_required`,
- When приходить відповідь,
- Then вона в черзі, напис «Чекає оновлення застосунку», банера відхилених немає.

**AC-3.2 (Після оновлення):**
- Given застосунок оновлено,
- When черга відправляється,
- Then операція `applied`.

## US-MFLAG-4 — OTA
Як користувач, я отримую зміни без перевстановлення і без переривань.

**AC-4.1 (Версія):**
- Given OTA з вищою логічною версією застосовано,
- When виконується запит,
- Then `X-App-Version` нова, `X-App-Native-Version` без змін.

**AC-4.2 (Холодний старт):**
- Given оновлення завантажено,
- When застосунок лишається відкритим,
- Then застосовується лише на наступному холодному старті.

**AC-4.3 (Активна сесія):**
- Given активна закупка і критичне оновлення,
- When повернення в застосунок,
- Then не застосовується; після завершення закупки — застосовується.

**AC-4.4 (Відкат):**
- Given оновлення падає на старті,
- When застосунок запускають знову,
- Then попередня версія працює, подія в Sentry.

## US-MFLAG-5 — Публікація
Як розробник, я не хочу випустити несумісне оновлення.

**AC-5.1 (Fingerprint):**
- Given змінено нативну залежність,
- When запускається OTA-джоб,
- Then він падає з вимогою нативної збірки.

**AC-5.2 (10%):**
- Given тег `mobile-ota-v*`,
- When публікується,
- Then rollout `production` 10%.

**AC-5.3 (Source maps):**
- Given опубліковано оновлення,
- When падіння в ньому,
- Then стек у Sentry символізовано.
