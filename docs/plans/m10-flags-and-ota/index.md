# M10 · Прапорці й OTA

Фіча-прапорці на клієнті, заглушки недоступних фіч, логічна версія застосунку і доставка змін через EAS Update без перевстановлення. Спирається на [B20](../20-feature-flags/index.md) і [фіча-прапорці](../../feature-flags.md).

Критерії приймання — у [юзер-сторі](user-stories.md).

**Порядок реалізації**: M1 → **M10** → M2 → … Модуль `expo-updates` має бути вже в першій збірці, а прапорці потрібні M2 (`scene.skia`, `auth.*`). B20 випереджає M2.

## Обсяг

- `useFeature`, кеш, оновлення набору, типізований реєстр.
- Обробка `403 feature.disabled` і `426 feature.upgrade_required`, черга операцій.
- Логічна версія застосунку.
- EAS Update: завантаження, застосування, канали, CI, відкат.

**Не входить**: правила й адмінка ([B20](../20-feature-flags/flags.md), [A7](../../roadmap.md#адмінка)), self-hosted сервер оновлень ([майбутнє](../../future.md)).

## Ключові рішення

| Рішення | Відкинуто | Чому |
|---|---|---|
| M10 одразу після M1 | За номером | Без `expo-updates` у першій збірці OTA неможливе |
| Реєстр прапорців генерується з бекенду | Ручний список | Новий ключ одразу типізований, значення не розходяться |
| `X-App-Version` — логічна версія JS-бандла | Semver нативної збірки | Інакше зміна, доставлена через OTA, все одно дає `426` |
| `426` спершу перевіряє OTA, потім стор | Одразу стор | Зайве перевстановлення — те, чого уникаємо |
| Застосування на холодному старті | Посеред сесії | Закупка чи готування не переривається |
| Операції `426` чекають окремо | Банер відхилених | Це не помилка користувача й не втрата даних |
| Спершу 10% production | Одразу 100% | Падіння зачепить менше людей |
