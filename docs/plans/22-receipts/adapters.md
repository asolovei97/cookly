# Адаптери

Як воркер перетворює сторінку чека на структуровані рядки.

## Інтерфейс

Адаптер — код у воркері, зареєстрований за **доменом** URL:

```
Match(url)  → чи цей адаптер обробляє URL
Fetch(url)  → сторінка чека
Parse(page) → магазин, адреса, дата, id чека, рядки, знижка, підсумки
Redact(page) → сторінка без платіжного блоку й даних лояльності
```

- Рядок: штрихкод чи код мережі, назва як у чеку, кількість, ціна за одиницю, сума.
- Невідомий домен → `unsupported`.
- Кожен адаптер має свій [прапорець](import.md#прапорці).
- Адаптер покривається тестами на збережених сторінках-фікстурах (без платіжних даних).

## elkasa (Сільпо)

- Домен `receipt.silpo.elkasa.com.ua`, сторінка — серверний HTML без капчі.
- Дає: продавця й адресу магазину, дату й час, фіскальний номер, id чека, рядки (`ШК`, обрізана назва, `кількість X ціна`, сума), знижку на чек, підсумки.
- Вагові товари — дробова кількість (`0.252 X 189.00`) і часто внутрішній код замість штрихкоду.
- Мережа — Сільпо.

## ДПС

- Домен `cabinet.tax.gov.ua`, сторінка — JS-застосунок.
- Адаптер — **окремий підпункт**, який стартує лише після **spike**: чи віддає сторінка позиції, чи є капча, чи є публічне API.
- Результат spike записується в [джерела даних](../../prices/sources.md#ціни).
- Як визначати мережу за продавцем — вирішується разом зі spike.

## Приватність

- `Redact` вирізає **платіжний блок** (маскована картка, банк, термінал, код авторизації, RRN) і дані **програми лояльності** — до будь-якого запису.
- **Сирий HTML** зберігається вже після `Redact`, **30 днів**, лише для налагодження адаптерів, без доступу клієнтів. Видаляє задача воркера.
- Розібрані рядки, магазин, дата й id чека зберігаються з імпортом.

## Мережа й місто

- **Мережа** — від адаптера (elkasa → Сільпо).
- **Місто** — за адресою магазину через довідник `cities`.
- Не впізнали → місто сім'ї; немає й його → ціни як за Україною ([B8](../08-prices/observations.md#місто-й-геолокація)).
