# Імпорт

Життєвий цикл чека від скану QR до підтвердження.

## Статуси

```
queued → parsed → confirmed
   │        └──→ cancelled
   ├──→ failed        (сторінка недоступна після 5 повторів)
   ├──→ unsupported   (невідомий домен або вимкнений адаптер)
   └──→ duplicate     (чек уже імпортовано)
```

- `queued` — URL прийнято, задача River у черзі.
- `parsed` — адаптер розібрав чек, рядки зіставлено ([зіставлення](matching.md)), **прев'ю** збережено на сервері.
- `confirmed` — користувач підтвердив; застосовано [наслідки](matching.md#наслідки).
- `cancelled` — користувач скасував прев'ю; дані розбору видаляються.
- `unsupported` — URL зберігається для статистики, які мережі додавати.

## Операції синхронізації

| Тип | Що робить | Офлайн |
|---|---|---|
| `receipt.submit@1` | URL з QR; `entityId` — id імпорту | Так: чекає в черзі клієнта |
| `receipt.confirm@1` | Рішення по рядках прев'ю, `shoppingId` (необов'язково) | Так, після завантаження прев'ю |
| `receipt.cancel@1` | Скасувати прев'ю | Так |

- Тип оголошує `feature: receipts` ([B20](../20-feature-flags/enforcement.md#синхронізація)).
- Підтвердження чека не в статусі `parsed` → `rejected` з `receipt.not_parsed`.
- Прев'ю змінилося після завантаження клієнтом (повторний розбір) → `rejected` з `receipt.stale`, клієнт перечитує.

## Дедуплікація

- Ключ — **`(домен, id чека)`**, **глобально** для всіх сімей.
- Той самий чек ще раз (своя чи інша сім'я) → статус `duplicate` і код `receipt.already_imported`.
- Скасований чек можна імпортувати знову.

## Давність

- Чек **не старший за 30 днів** від дати в чеку. Дату видно лише після розбору, тож старший чек отримує статус `failed` з кодом `receipt.too_old`.
- **Дата чека** стає датою спостережень цін, датою факту бюджету і часом записів в історії запасів — обмеження `clientTime` у 7 днів ([B14](../14-offline-sync/protocol.md#час)) тут не діє, бо дата береться з чека.

## Ліміти

| Що | Ліміт | Перевищення |
|---|---|---|
| Чеки на сім'ю | 30 на добу | `429 receipt.rate_limited` |
| Запити воркера на домен | Не більше N за хвилину, решта чекає в черзі | — |
| Повтори завантаження | 5, з backoff | `failed` |

## Прапорці

| Ключ | Тип | Що вимикає |
|---|---|---|
| `receipts` | `optional` | Усю фічу: ендпоінти, операції, задачі |
| `receipts.elkasa` | `optional` | Адаптер Сільпо: його домен стає `unsupported` |
| `receipts.dps` | `optional` | Адаптер ДПС |

Задача воркера вимкненої фічі — `skipped` ([B20](../20-feature-flags/enforcement.md#воркер)).

## Ендпоінти (онлайн)

| Метод і шлях | Що робить |
|---|---|
| `GET /v1/receipts/{id}` | Статус і прев'ю: магазин, дата, рядки, зіставлення, підсумки |
| `GET /v1/receipts?status=` | Чеки сім'ї |
| `PATCH /v1/receipts/{id}/lines/{lineId}` | Змінити зіставлення рядка в прев'ю (онлайн-варіант до підтвердження) |

Створення, підтвердження й скасування — через `POST /v1/sync/ops`.
