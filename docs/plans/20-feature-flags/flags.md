# Прапорці

Реєстр фіч, правила таргетингу, групи й адмін-ендпоінти.

## Реєстр

- Фічі оголошуються **в коді**: ключ (`shopping`, `receipts`, `llm.cook_from_pantry`), тип `core` | `optional`, `public` (так/ні), опис.
- Міграція створює прапорець з початковим станом: `core` — увімкнений, `optional` — вимкнений.
- Адмін **не створює** й не видаляє ключі — лише редагує правила. Ключ, якого вже немає в коді, позначається `retired` і не повертається клієнтам.
- CI перевіряє, що кожен `x-feature` у контракті і кожен `feature` у реєстрі типів операцій [B14](../14-offline-sync/protocol.md#реєстр-типів) є в реєстрі фіч.

## Прапорець

| Поле | Примітка |
|---|---|
| `enabled` | Глобальний перемикач |
| `denyHouseholds`, `denyAccounts` | Список заборони |
| `platforms` | `ios`, `android`; порожньо — усі |
| `minAppVersion`, `maxAppVersion` | Діапазон версій для таргетингу, окремо для кожної платформи |
| `allowGroups` | Групи сімей і користувачів |
| `rolloutPercent` | 0–100 |
| `minFeatureVersion` | Мінімальна версія застосунку для фічі, окремо для кожної платформи, див. [застосування](enforcement.md#версія-фічі) |

- Тип булевий; у відповіді є `variant`, у MVP завжди `null`.
- **Кор-фічі** (`core`) мають лише `enabled` і `minFeatureVersion`; групи, списки й відсоток для них недоступні → `422 feature.core_rules`.

## Обчислення

Для контексту (сім'я, акаунт, платформа, версія):

1. `enabled = false` → off.
2. Сім'я чи акаунт у списку заборони → off.
3. Платформа чи версія поза таргетингом → off.
4. Сім'я чи акаунт у групі з `allowGroups` → on.
5. Інакше on, якщо `hash(flagKey + householdId) mod 100 < rolloutPercent`; акаунт без сім'ї — за `accountId`.

- Хеш стабільний: збільшення відсотка лише додає сім'ї, а ті, хто вже мав фічу, її не втрачають.
- `minFeatureVersion` у порядок не входить: фіча може бути on, але версія застосунку застара → `426` ([застосування](enforcement.md#версія-фічі)).

## Публічні прапорці

- Фічі з `public: true` (вхід через Google, новий онбординг) обчислюються **без токена** — лише за `enabled`, платформою й версією; групи, списки й відсоток до входу не застосовуються.
- Решту прапорців без токена не видно.

## Групи

- Два типи: **групи сімей** і **групи користувачів**.
- Створює й редагує `admin`; учасники додаються пошуком (сім'я — за власником чи id, користувач — за email чи id).
- Одна група може бути в правилах кількох прапорців.
- Спільні фічі (закупка, план) таргетуються на сім'ї; особисті й тестові — на користувачів (`internal`).

## Небезпечні зміни

- Вимкнення **кор-фічі**, підвищення `minFeatureVersion` чи глобальної мінімальної версії вимагають **причини** й **подвійного підтвердження** (`confirm: true` після прев'ю, скільки сімей зачепить зміна).
- Без причини → `422 feature.reason_required`.

## Аудит і застарілі

- Кожна зміна правил і груп пишеться в [аудит](../03-admin-auth/audit-and-users.md): хто, коли, до і після, причина.
- Прапорець `optional`, увімкнений на 100% без обмежень понад **30 днів**, позначається **«застарілий»** — кандидат на видалення з коду.

## Адмін-ендпоінти

Право `features.manage` — лише `admin` ([B3](../03-admin-auth/access.md#ролі-й-права)).

| Метод і шлях | Що робить |
|---|---|
| `GET /admin/v1/features` | Прапорці зі статусом, правилами, позначкою «застарілий» |
| `PATCH /admin/v1/features/{key}` | Змінити правила, з причиною |
| `POST /admin/v1/features/{key}/impact` | Прев'ю зміни: скільки сімей зачепить |
| `GET /admin/v1/features/preview?householdId=&accountId=&platform=&version=` | Що отримає конкретна сім'я чи користувач |
| `GET`/`POST`/`PATCH`/`DELETE /admin/v1/feature-groups` | Групи й учасники |
| `GET`/`PUT /admin/v1/settings/min-app-version` | Глобальна мінімальна версія, див. [застосування](enforcement.md#глобальна-мінімальна-версія) |
