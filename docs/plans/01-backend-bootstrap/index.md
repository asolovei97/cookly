# B1 · Бутстрап бекенду

Каркас, на якому будуються всі наступні пункти [роадмапу](../../roadmap.md): структура коду, контракт API, формат помилок, спостережуваність, база даних, воркер, інструменти й CI. Бізнес-функцій тут немає.

Критерії приймання — у [юзер-сторі](user-stories/index.md).

## Обсяг

- Монорепо, Go-модуль `backend/` з `cmd/api` і `cmd/worker`.
- Конфіг з оточення з валідацією.
- OpenAPI-контракт, кодогенерація Go-сервера і TS-клієнта.
- Єдиний формат помилок, безпека за замовчуванням.
- Логи, `request_id`, метрики, трасування, крашлітика, health-перевірки.
- PostgreSQL, міграції, sqlc, Redis, Garage, черга River.
- Makefile, Docker Compose для інфраструктури, Docker-образ, CI.
- `GET /v1/ping`.

## Ключові рішення

| Рішення | Відкинуто | Чому |
|---|---|---|
| `net/http` + oapi-codegen strict-server | gin, chi | Стандартний mux з Go 1.22 вміє метод і параметри шляху; strict-server дає типізовані запити; стандартні middleware без адаптерів |
| sqlc + goose | ent + Atlas | Багато SQL-специфічного (медіана, materialized view, JSONB, trigram, рекурсія); ent тягне свої міграції і рантайм |
| River (черга на PostgreSQL) | RabbitMQ, asynq | Задача ставиться в тій самій транзакції, що й дані; немає окремої інфраструктури; вбудовані повтори й періодичні задачі |
| pnpm workspaces, TS-клієнт уже в B1 | bun, deno; клієнт пізніше | pnpm найзріліший для монорепо з Expo; deno не підтримує RN; контракт і клієнт змінюються разом |
| Згенерований код комітимо | Генерація під час збірки | Проєкт збирається одразу після клону, вплив зміни контракту видно в рев'ю |
| Лише додаткові зміни в `/v1`, `oasdiff` у CI, мінімальна версія застосунку в middleware | Вільні зміни контракту | Старі версії мобільного застосунку живуть місяцями; несумісну зміну можна лише через `/v2` або примусове оновлення |
| Окрема команда `migrate` | Міграції на старті API | Контрольований деплой; API не стартує, якщо схема відстає |
| Docker у development лише для інфраструктури | Усе в Docker | Швидший цикл з `air`; образ потрібен лише для staging і production |
