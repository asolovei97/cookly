# Дані й воркер

PostgreSQL, міграції, доступ до даних, Redis, черга задач і файлове сховище.

## PostgreSQL

- Версія 18, драйвер `pgx/v5` з пулом.
- Ідентифікатори — UUIDv7, час — `timestamptz` в UTC.
- Транзакції — через хелпер у `internal/platform/db`, щоб сервіс міг об'єднати кілька запитів sqlc і постановку задачі в одній транзакції.

## Міграції

- **goose**, файли в `backend/migrations/`, вбудовані в бінарник через `embed`.
- Запускаються **окремою командою** `api migrate up` (`make migrate` локально; job перед деплоєм у середовищах).
- Повторний запуск `migrate up` без нових міграцій нічого не змінює.
- **API не стартує, якщо схема відстає** від версії бінарника: процес завершується з помилкою. *Чому*: це означає помилку деплою, і про неї краще дізнатися одразу. *Відкинуто*: міграції на старті API (гонки між репліками, неконтрольований деплой) і `503` у `/readyz` (помилка ховається).

## sqlc

- SQL у `queries.sql` кожного домену, згенерований код під pgx — у підпакеті `db/` домену.
- sqlc перевіряє запити проти схеми з міграцій на етапі генерації.
- *Відкинуто*: ent — див. [ключові рішення](index.md#ключові-рішення).

## Redis

- Ліміти запитів, одноразові значення (`nonce`, коди OTP у B2), кеш.
- Не використовується як черга.

## Воркер і черга

- **River** — черга задач на PostgreSQL.
- Задача ставиться **в тій самій транзакції**, що й зміна даних: якщо транзакцію відкотили, задачі немає.
- Вбудовані повтори з відкладанням, відкладені, періодичні й унікальні задачі; River UI для перегляду.
- `cmd/worker` — окремий бінарник у тому ж модулі. У B1: запуск, реєстрація задач, тестова задача, коректна зупинка (задачі, що вже виконуються, завершуються до таймауту).
- Міграції River застосовуються разом із міграціями застосунку.

| | River | RabbitMQ |
|---|---|---|
| Інфраструктура | Наявний PostgreSQL | Окремий сервіс |
| Узгодженість з даними | Транзакційна постановка | Потрібен outbox |
| Повтори, відкладені, періодичні задачі | Вбудовано | Плагіни або вручну |
| Пропускна здатність | Тисячі задач за секунду — достатньо | Значно вища |

RabbitMQ має сенс, якщо з'являться кілька сервісів, обмін подіями між ними або дуже великий потік. Тоді його можна додати поруч з River.
