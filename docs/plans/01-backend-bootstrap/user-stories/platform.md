# Юзер-сторі — платформа API

US-BOOT-1…7. Загальні правила — в [індексі юзер-сторі](index.md).

## US-BOOT-1 — Перевірка доступності API
Як розробник клієнта, я хочу перевірити, що API доступне, без токена.

**AC-1.1 (Ping без токена):**
- Given API запущене,
- When клієнт викликає `GET /v1/ping` без заголовка `Authorization`,
- Then повертається `200` з `{"status": "ok"}`.

**AC-1.2 (Невідомий маршрут):**
- Given API запущене,
- When клієнт викликає `GET /v1/unknown`,
- Then повертається `404` з `code: request.not_found` у форматі `application/problem+json`.

## US-BOOT-2 — Єдиний формат помилок
Як розробник клієнта, я хочу отримувати всі помилки в одному форматі, щоб обробляти їх за кодом.

**AC-2.1 (Тіло не JSON):**
- Given операція приймає JSON-тіло,
- When клієнт надсилає тіло, яке не розбирається як JSON,
- Then повертається `400` з `code: request.malformed`.

**AC-2.2 (Порушення контракту):**
- Given у тілі бракує обов'язкового поля або поле має неправильний тип,
- When клієнт надсилає запит,
- Then повертається `422` з `code: request.invalid` і `errors[]`, де `pointer` вказує на поле (наприклад `/name`).

**AC-2.3 (Метод не підтримується):**
- Given маршрут існує лише для `GET`,
- When клієнт надсилає `DELETE`,
- Then повертається `405` з `code: request.method_not_allowed`.

**AC-2.4 (Обов'язкові поля помилки):**
- Given будь-яка помилкова відповідь,
- When клієнт її отримує,
- Then вона має `Content-Type: application/problem+json` і поля `code`, `message`, `requestId`.

## US-BOOT-3 — Ідентифікатор запиту
Як розробник, я хочу знайти всі логи конкретного запиту за його ідентифікатором.

**AC-3.1 (Свій ідентифікатор клієнта):**
- Given клієнт надсилає `X-Request-ID` до 64 символів з `[A-Za-z0-9-_]`,
- When запит обробляється,
- Then той самий ідентифікатор повертається в заголовку `X-Request-ID`, у `requestId` помилок і в кожному лозі цього запиту.

**AC-3.2 (Невалідний або відсутній ідентифікатор):**
- Given `X-Request-ID` відсутній, довший за 64 символи або містить недозволені символи,
- When запит обробляється,
- Then сервер генерує новий ідентифікатор і використовує його замість клієнтського.

## US-BOOT-4 — Захищено за замовчуванням
Як розробник, я хочу, щоб нова операція без явної позначки була захищена, щоб випадково не відкрити дані.

**AC-4.1 (Захищена операція без токена):**
- Given у контракті є операція без `security: []`,
- When клієнт викликає її без access-токена,
- Then повертається `401` з `code: auth.unauthorized`.

**AC-4.2 (Публічна операція):**
- Given операція позначена `security: []` (як `GET /v1/ping`),
- When клієнт викликає її без токена,
- Then запит обробляється звичайно.

## US-BOOT-5 — Збій не зупиняє сервер
Як оператор, я хочу, щоб panic в одному запиті не впливав на інші, а збій потрапляв у крашлітику.

**AC-5.1 (Panic в обробнику):**
- Given обробник викликає panic,
- When клієнт надсилає запит,
- Then повертається `500` з `code: internal.error` і `requestId`, у крашлітику йде подія з цим `request_id`, а наступні запити обробляються звичайно.

**AC-5.2 (Крашлітику не налаштовано):**
- Given DSN не задано,
- When стається panic,
- Then відповідь така сама, як в AC-5.1, а відправка подій не відбувається і не спричиняє помилок.

## US-BOOT-6 — Безпечний конфіг
Як оператор, я хочу, щоб API не стартувало з помилковим конфігом.

**AC-6.1 (Бракує обов'язкового значення):**
- Given не задано обов'язкову змінну (наприклад, адресу PostgreSQL),
- When запускається API або воркер,
- Then процес завершується з ненульовим кодом і повідомленням, якої змінної бракує.

**AC-6.2 (Невідоме оточення):**
- Given `ENV` не є `development`, `staging` чи `production`,
- When запускається процес,
- Then він завершується з помилкою конфігу.

**AC-6.3 (Налаштування лише для розробки):**
- Given `ENV=staging` або `ENV=production` і ввімкнено налаштування, дозволене лише в `development`,
- When запускається процес,
- Then він завершується з помилкою конфігу.

## US-BOOT-7 — Health і метрики
Як оператор, я хочу знати, чи сервіс живий і готовий, і бачити його метрики.

**AC-7.1 (Готовність):**
- Given PostgreSQL і Redis доступні,
- When оркестратор викликає `/readyz` на службовому порту,
- Then повертається `200`.

**AC-7.2 (Залежність недоступна):**
- Given PostgreSQL або Redis не відповідає,
- When викликається `/readyz`,
- Then повертається `503`, а `/healthz` і далі повертає `200`.

**AC-7.3 (Метрики):**
- Given API обробило запит до `/v1/ping`,
- When викликається `/metrics` на службовому порту,
- Then у відповіді є лічильник HTTP-запитів з шаблоном маршруту і статусом.

**AC-7.4 (Службові ендпоінти не публічні):**
- Given API запущене,
- When клієнт викликає `/metrics`, `/healthz` чи `/readyz` на публічному порту,
- Then повертається `404`.
