# Юзер-сторі — видалення акаунта

Критерії приймання для [плану видалення акаунта](index.md). AC перевіряються на рівні API і задач воркера. Кожен AC покривається тестом з назвою `TestAC_<US>_<N>_...`.

## US-DEL-1 — Запит
Як користувач, я хочу видалити акаунт, не ламаючи сім'ю.

**AC-1.1 (`owner` з учасниками):**
- Given `owner` і ще один учасник з акаунтом,
- When `owner` викликає `DELETE /v1/me`,
- Then `409 household.owner_must_transfer`, статус акаунта не змінився.

**AC-1.2 (Позначка для сім'ї):**
- Given учасник у `pending_deletion`,
- When інший учасник читає склад сім'ї,
- Then персона має позначку «акаунт видаляється», а її вага не повертається.

## US-DEL-2 — Заблокований акаунт
Як заблокований користувач, я хочу мати змогу видалити акаунт.

**AC-2.1 (Квиток видалення):**
- Given акаунт заблоковано до дати в майбутньому,
- When він входить через Apple,
- Then `403 auth.account_suspended` з `until` і квитком видалення, токенів немає.

**AC-2.2 (Запит за квитком):**
- Given дійсний квиток видалення,
- When `POST /v1/auth/delete`,
- Then акаунт `pending_deletion`.

**AC-2.3 (Відновлення не знімає блокування):**
- Given заблокований акаунт у `pending_deletion` відновили,
- When він входить, поки блокування діє,
- Then `403 auth.account_suspended`.

## US-DEL-3 — Анонімізація акаунта
Як користувач, я хочу, щоб після видалення про мене не лишилося персональних даних.

**AC-3.1 (Надгробок):**
- Given акаунт у `pending_deletion` 31 день,
- When виконується задача анонімізації,
- Then email, ім'я, прив'язки, сесії й пристрої видалено, акаунт `deleted`, а посилання на нього валідні.

**AC-3.2 (Повтор невдалого кроку):**
- Given відкликання токена Apple не вдалося,
- When задача виконується знову наступного дня,
- Then крок повторюється, а `deleted` ставиться лише після його успіху.

**AC-3.3 (Ідемпотентність):**
- Given крок анонімізації запасів уже виконано,
- When його запускають ще раз,
- Then дані не змінюються, помилки немає.

## US-DEL-4 — Персона після видалення
Як учасник сім'ї, я хочу далі планувати порції на цю людину, але не бачити її приватних даних.

**AC-4.1 (Персона без акаунта):**
- Given анонімізовано акаунт тата, а в сім'ї лишилася мама,
- When мама читає персону тата,
- Then персона без акаунта з тим самим ім'ям і параметрами, без історії ваги, норма — ручна з останнім значенням.

**AC-4.2 (Записи лишаються):**
- Given записи з'їденого тата за місяць,
- When мама читає статистику,
- Then записи на місці.

## US-DEL-5 — Загальні дані й сім'я
Як користувач, я хочу, щоб загальні дані не зламалися, а дані сім'ї зникли разом зі мною.

**AC-5.1 (Ціни анонімно):**
- Given акаунт залишив 20 спостережень цін,
- When його анонімізовано,
- Then спостереження лишаються в медіанах з автором «видалений користувач».

**AC-5.2 (Останній акаунт):**
- Given акаунт — єдиний у сім'ї з планом, запасами й записами,
- When його анонімізовано,
- Then сім'я, її персони й дані видалено, а схвалена публічна копія рецепта лишилася без імені автора.

**AC-5.3 (Недомодероване):**
- Given товар сім'ї в черзі модерації,
- When сім'ю видалено,
- Then товар видалено з черги.

## US-DEL-6 — Видалення історії ваги
Як персона, я хочу прибрати свою історію ваги, не видаляючи акаунт.

**AC-6.1 (Сама персона):**
- Given персона з акаунтом і 30 записами ваги, норма за формулою 2100 ккал,
- When вона викликає `DELETE /v1/household/persons/{id}/weight-history`,
- Then записів ваги немає, норма — ручна 2100 ккал.

**AC-6.2 (Інший учасник):**
- Given персона з акаунтом,
- When інший учасник викликає цей ендпоінт для неї,
- Then `403 household.forbidden`.
