# Юзер-сторі — переклади

Критерії приймання для [плану перекладів](index.md). AC перевіряються на рівні API (контентні — на тестовій таблиці) або CLI. Кожен AC покривається тестом з назвою `TestAC_<US>_<N>_...`.

## US-I18N-1 — Контент моєю мовою
Як користувач, я хочу бачити контент своєю мовою, а якщо перекладу немає — хоча б оригінал.

**AC-1.1 (Є переклад):**
- Given запис з `name: {"uk": "Борщ", "en": "Borscht"}` і користувач з мовою `en`,
- When клієнт запитує запис,
- Then повертається `"name": "Borscht"` без `nameLang`.

**AC-1.2 (Запасний варіант):**
- Given запис лише з `uk` і користувач з мовою `en`,
- When клієнт запитує запис,
- Then повертається `"name": "Борщ"` і `"nameLang": "uk"`.

**AC-1.3 (Запит без токена):**
- Given публічний запит без токена з `Accept-Language: en`,
- When клієнт запитує запис з перекладом `en`,
- Then повертається значення `en`; без заголовка — значення `uk`.

## US-I18N-2 — Контент від користувача
Як користувач, я хочу писати своєю мовою і не перекладати нічого.

**AC-2.1 (Створення):**
- Given користувач з мовою `en`,
- When він створює запис з `name: "Pancakes"`,
- Then зберігається `{"en": "Pancakes"}` і `source_lang: en`.

## US-I18N-3 — Редагування перекладів
Як перекладач, я хочу доповнювати й виправляти переклади глобального контенту.

**AC-3.1 (Збереження мапи):**
- Given `translator` в адмінці,
- When він зберігає `{"uk": "Борщ", "en": "Borscht"}`,
- Then обидва значення зберігаються, а в аудиті з'являється запис.

**AC-3.2 (Непідтримувана мова):**
- Given мови `de` немає в `languages`,
- When адмін зберігає мапу з ключем `de`,
- Then повертається `422` з кодом `i18n.unsupported_language`.

**AC-3.3 (Без права):**
- Given адмін лише з роллю `moderator`,
- When він зберігає переклад,
- Then повертається `403` з кодом `admin.forbidden`.

## US-I18N-4 — Застарілі переклади
Як перекладач, я хочу знати, які переклади відстали від оригіналу.

**AC-4.1 (Зміна оригіналу):**
- Given запис з `source_lang: uk` і перекладом `en`,
- When змінюється значення `uk`,
- Then `en` додається в `i18n_outdated`, а API застосунку й далі віддає старий `en`.

**AC-4.2 (Оновлення перекладу):**
- Given `en` у `i18n_outdated`,
- When перекладач зберігає нове значення `en`,
- Then `en` прибирається з `i18n_outdated`.

## US-I18N-5 — Черга перекладів
Як перекладач, я хочу бачити, що треба перекласти.

**AC-5.1 (Неперекладене й застаріле):**
- Given глобальні записи без `en` і з `en` в `i18n_outdated`,
- When перекладач відкриває чергу з фільтром `en`,
- Then перші є у вкладці «неперекладене», другі — у «застаріле».

**AC-5.2 (Приватний контент):**
- Given приватний запис сім'ї без перекладу,
- When перекладач відкриває чергу,
- Then цього запису в черзі немає.

## US-I18N-6 — Пошук
Як користувач, я хочу знаходити продукти й рецепти незалежно від мови оригіналу.

**AC-6.1 (Пошук мовою оригіналу):**
- Given запис лише з `uk: "Борщ"` і користувач з мовою `en`,
- When він шукає «борщ»,
- Then запис знаходиться.

**AC-6.2 (Апострофи):**
- Given запис «М'ясо» з прямим апострофом,
- When користувач шукає «мʼясо» чи «м’ясо»,
- Then запис знаходиться.

## US-I18N-7 — Мови
Як адмін, я хочу підготувати нову мову, перш ніж показати її користувачам.

**AC-7.1 (Вимкнена мова):**
- Given мова `de` є в `languages`, але вимкнена, а запис має переклад `de`,
- When користувач з `Accept-Language: de` запитує запис,
- Then повертається запасний варіант, а не `de`.

**AC-7.2 (Увімкнення):**
- Given адмін увімкнув `de`,
- When той самий користувач запитує запис,
- Then повертається значення `de`.

## US-I18N-8 — Пакет рядків
Як мобільний застосунок, я хочу отримувати актуальні тексти без релізу.

**AC-8.1 (Пакет без токена):**
- Given мова `uk` увімкнена,
- When клієнт викликає `GET /v1/i18n/uk` без токена,
- Then повертається `200` з `version`, `strings` і заголовком `ETag`.

**AC-8.2 (Без змін):**
- Given клієнт має поточний `ETag`,
- When він надсилає запит з `If-None-Match`,
- Then повертається `304`.

**AC-8.3 (Після правки):**
- Given адмін змінив рядок `uk`,
- When клієнт запитує пакет `uk` зі старим `ETag`,
- Then повертається `200` з більшою `version` і новим текстом.

**AC-8.4 (Невідома мова):**
- Given мова невідома або вимкнена,
- When клієнт запитує її пакет,
- Then повертається `404` з кодом `i18n.language_not_found`.

## US-I18N-9 — Перевірка повідомлень
Як перекладач, я хочу, щоб зламаний текст не потрапив у застосунок.

**AC-9.1 (Невалідний синтаксис):**
- Given текст з незакритою дужкою ICU,
- When перекладач зберігає його,
- Then повертається `422` з кодом `i18n.invalid_message`, і рядок не змінюється.

**AC-9.2 (Бракує форм множини):**
- Given `uk`-текст з `plural` лише з формами `one` і `other`,
- When перекладач зберігає його,
- Then повертається `422` з кодом `i18n.invalid_message`.

## US-I18N-10 — Синхронізація ключів
Як розробник, я хочу додавати ключі в коді, не затираючи правки адмінів.

**AC-10.1 (Нові ключі):**
- Given у файлі `i18n/mobile/uk.json` з'явився новий ключ,
- When запускається `api i18n sync`,
- Then ключ з'являється в БД і в пакеті.

**AC-10.2 (Правки адміна):**
- Given адмін відредагував рядок, а у файлі для нього інше значення,
- When запускається `api i18n sync`,
- Then значення адміна лишається.

**AC-10.3 (Видалені ключі):**
- Given ключа більше немає у файлах,
- When запускається `api i18n sync`,
- Then ключ позначається `deprecated` і зникає з пакета, але лишається в БД.

**AC-10.4 (Експорт):**
- Given у БД є правки адміна,
- When запускається `api i18n export`,
- Then файли `i18n/mobile/<lang>.json` містять актуальні значення.
