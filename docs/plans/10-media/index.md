# B10 · Медіа

Фото рецептів і приготувань, сховище Garage, прев'ю, а також генератор піксельних картинок і спрайти для нього. Продуктовий опис — у [фото](../../recipes/media.md) і [піксельних картинках](../../recipes/pixel-art.md).

Критерії приймання — у [юзер-сторі](user-stories.md).

## Обсяг

- Завантаження через presigned URL, хелпер `uploadMedia` в `packages/api-client`.
- Перевірка форматів, прев'ю, видалення EXIF.
- Бакети `public` і `private`, видача файлів.
- Квоти, очищення неприв'язаних файлів.
- Генератор піксельних картинок, CLI, процедурні заглушки.
- Специфікація спрайтів, палітра, маніфест, промпт для агента-дизайнера, кроки в Pixelorama.
- Перевірка Garage у `/readyz`.

**Не входить**: модерація обкладинок публічних рецептів ([B11](../../roadmap.md#бекенд)), прив'язка фото до готування ([B16](../../roadmap.md#бекенд)), фото кроків ([майбутнє](../../future.md)).

## Ключові рішення

| Рішення | Відкинуто | Чому |
|---|---|---|
| Presigned URL + хелпер `uploadMedia` | `multipart` у `POST`/`PATCH` рецепта | Повтор лише файлу при обриві; офлайн-синхронізація даних не чекає на фото; мегабайти не йдуть через API; контракт лишається JSON |
| Клієнт конвертує в JPEG і зменшує до 2048 px | Приймати HEIC | Декодування HEIC у Go потребує cgo |
| Прев'ю на чистому Go | libvips | Без cgo, образ лишається distroless; libvips — запасний варіант |
| Два бакети: `public` і `private` | Усе через presigned GET; усе публічне | Публічне кешується CDN, приватне фото сім'ї не доступне за прямим посиланням |
| Піксельна картинка лише для рецепта | Також для кожного готування | Достатньо; готування без фото показує картинку рецепта |
| Процедурні заглушки до появи спрайтів | Чекати на спрайти | Функція працює з першого дня |
| Агент генерує PNG кодом, автор доправляє в Pixelorama | Малювати все з нуля | Швидко отримати повний набір у єдиній палітрі |

## Що таке cgo і чому libvips — запасний варіант

**cgo** — механізм, через який Go-код викликає бібліотеки на C. Ціна:

- для збірки потрібні компілятор C і самі C-бібліотеки;
- бінарник не самодостатній: в образ треба класти libc і libvips, тож мінімальний distroless `static` не підходить;
- складніше збирати під іншу платформу;
- помилка в C-коді може обвалити процес, і `recover` у Go від неї не рятує.

**libvips** (через govips) швидший і вміє WebP / AVIF на виході. Переходимо на нього, лише якщо чистого Go забракне за швидкістю чи форматами.

## Open questions

- Чи зберігати оригінал (з EXIF) після створення прев'ю, чи видаляти його: впливає на квоту і приватність.
- Ліміти й квоти (10 МБ, 50 на добу, 2 ГБ) — початкові значення, перевірити на реальному використанні.
