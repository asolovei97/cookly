# Аудит і користувачі

Журнал дій адмінів і керування користувачами застосунку.

## Аудит

Що пишеться:

- **кожна дія адміна, що змінює дані**: хто, що (тип сутності й id), стан до і після (diff), IP, час, `request_id`;
- **події входу**: успіх, невдача, налаштування й скидання 2FA, блокування після невдалих спроб.

Правила:

- Журнал **лише доповнюється**: API не має операцій для зміни чи видалення записів.
- Читати журнал може лише `admin`, з фільтрами за адміном, сутністю й періодом.
- **Зберігання**: дії — безстроково; події входу (з IP) — 1 рік, після чого їх видаляє періодична задача воркера (River).

## Користувачі застосунку

Права — з [матриці](access.md#ролі-й-права): `admin` і `moderator`.

- **Пошук і перегляд**: ім'я, id, статус, дата реєстрації, прив'язані провайдери, сім'я.
- **Блокування до дати з причиною**: встановлює `suspendedUntil` з [B2](../02-app-auth/protection.md#блокування) і **відкликає всі сесії** користувача. Вхід у застосунок повертає `403 auth.account_suspended`.
- **Розблокування**: очищає `suspendedUntil`.
- Кожна дія пишеться в аудит.

## Залежності

- [B2](../02-app-auth/index.md) — поле `suspendedUntil` і сесії користувачів.
- [B1](../01-backend-bootstrap/data-and-worker.md#воркер-і-черга) — воркер для очищення подій входу.
