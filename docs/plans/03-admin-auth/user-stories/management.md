# Юзер-сторі — керування

US-ADM-6…8. Загальні правила — в [індексі юзер-сторі](index.md).

## US-ADM-6 — Керування адмінами
Як `admin`, я хочу додавати адмінів, змінювати їхні ролі й відключати доступ.

**AC-6.1 (Створення адміна):**
- Given `admin` в адмінці,
- When він створює адміна з email і ролями,
- Then повертається одноразове посилання для налаштування на 24 години, а в аудиті з'являється запис.

**AC-6.2 (Зміна ролей):**
- Given адмін з роллю `translator`,
- When `admin` додає йому роль `moderator`,
- Then наступний запит цього адміна до модерації виконується.

**AC-6.3 (Деактивація):**
- Given адмін має активну сесію,
- When `admin` деактивує його,
- Then наступний запит з цією сесією повертає `401`, а вхід — `admin.invalid_credentials`.

**AC-6.4 (Скидання 2FA):**
- Given адмін втратив пристрій з TOTP,
- When `admin` скидає йому 2FA,
- Then усі сесії цього адміна відкликаються, і видається нове посилання для налаштування.

**AC-6.5 (Останній admin):**
- Given у системі лише один активний `admin`,
- When хтось намагається його деактивувати чи зняти з нього роль `admin`,
- Then повертається `409` з кодом `admin.last_admin`.

**AC-6.6 (Дія щодо себе):**
- Given `admin` в адмінці,
- When він намагається деактивувати себе чи зняти з себе роль `admin`,
- Then повертається `409` з кодом `admin.self_action_forbidden`.

## US-ADM-7 — Блокування користувачів застосунку
Як модератор, я хочу заблокувати порушника до певної дати.

**AC-7.1 (Блокування):**
- Given активний користувач застосунку з сесіями,
- When `moderator` блокує його до дати в майбутньому з причиною,
- Then встановлюється `suspendedUntil`, усі сесії користувача відкликаються, вхід у застосунок повертає `403 auth.account_suspended`, а в аудиті з'являється запис з причиною.

**AC-7.2 (Розблокування):**
- Given заблокований користувач,
- When `moderator` розблоковує його,
- Then `suspendedUntil` очищується, і користувач може увійти.

**AC-7.3 (Без права):**
- Given адмін лише з роллю `translator`,
- When він намагається заблокувати користувача,
- Then повертається `403` з кодом `admin.forbidden`.

## US-ADM-8 — Аудит
Як `admin`, я хочу бачити, хто і що змінив.

**AC-8.1 (Запис дії):**
- Given `moderator` змінює дані (наприклад, блокує користувача),
- When дія завершується,
- Then в аудиті є запис з адміном, сутністю, diff до і після, IP, часом і `request_id`.

**AC-8.2 (Доступ до журналу):**
- Given адмін без ролі `admin`,
- When він запитує журнал аудиту,
- Then повертається `403` з кодом `admin.forbidden`.

**AC-8.3 (Незмінність):**
- Given адмін-контракт,
- When виконується тест контракту,
- Then у ньому немає операцій для зміни чи видалення записів аудиту.

**AC-8.4 (Очищення подій входу):**
- Given є події входу старші за рік і новіші,
- When спрацьовує періодична задача воркера,
- Then старі події входу видаляються, а новіші й записи дій лишаються.
