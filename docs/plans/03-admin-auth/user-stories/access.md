# Юзер-сторі — доступ і сесії

US-ADM-1…5. Загальні правила — в [індексі юзер-сторі](index.md).

## US-ADM-1 — Перший адмін
Як власник проєкту, я хочу створити першого адміна без адмінки.

**AC-1.1 (Створення через CLI):**
- Given у системі немає адміна з цим email,
- When запускається `api admin create --email … --role admin`,
- Then створюється адмін і виводиться одноразове посилання для налаштування, яке діє 24 години.

**AC-1.2 (Email уже зайнятий):**
- Given адмін з цим email існує,
- When запускається та сама команда,
- Then команда завершується з помилкою, і нічого не змінюється.

## US-ADM-2 — Налаштування за посиланням
Як новий адмін, я хочу задати пароль і TOTP за посиланням, яке мені передали.

**AC-2.1 (Успішне налаштування):**
- Given чинне посилання,
- When адмін задає пароль від 12 символів, якого немає в списку поширених, і підтверджує TOTP правильним кодом,
- Then акаунт стає активним, видаються 10 кодів відновлення, а посилання стає недійсним.

**AC-2.2 (Посилання прострочене або використане):**
- Given минуло понад 24 години або посиланням уже скористалися,
- When адмін відкриває його,
- Then повертається `401` з кодом `admin.setup_expired`.

**AC-2.3 (Слабкий пароль):**
- Given пароль коротший за 12 символів або є в списку поширених,
- When адмін надсилає його,
- Then повертається `422` з кодом `admin.weak_password`, а посилання лишається чинним.

**AC-2.4 (Неправильний код TOTP):**
- Given адмін відсканував секрет TOTP,
- When він підтверджує неправильним кодом,
- Then повертається `422` з `errors[]` для `/totpCode`, і 2FA не вмикається.

## US-ADM-3 — Вхід
Як адмін, я хочу безпечно входити в адмінку.

**AC-3.1 (Успішний вхід):**
- Given активний адмін,
- When він надсилає правильні email, пароль і код TOTP,
- Then створюється сесія, і браузер отримує cookie з `HttpOnly`, `Secure`, `SameSite=Strict`.

**AC-3.2 (Неправильні дані):**
- Given email не існує, пароль неправильний або код TOTP неправильний,
- When адмін намагається увійти,
- Then повертається `401` з кодом `admin.invalid_credentials`, однаковий для всіх трьох випадків.

**AC-3.3 (Код відновлення):**
- Given адмін має невикористаний код відновлення,
- When він входить з ним замість TOTP,
- Then вхід успішний, а повторний вхід з тим самим кодом повертає `admin.invalid_credentials`.

**AC-3.4 (Блокування після невдалих спроб):**
- Given було 5 невдалих спроб поспіль,
- When надходить ще одна спроба, навіть з правильними даними,
- Then повертається `429` з кодом `admin.locked` і заголовком `Retry-After`, доки не мине 15 хвилин.

**AC-3.5 (Ліміт з IP):**
- Given з одного IP перевищено ліміт запитів на вхід,
- When надходить ще один запит,
- Then повертається `429` з заголовком `Retry-After`.

## US-ADM-4 — Сесія
Як адмін, я хочу, щоб моя сесія була захищена і не жила вічно.

**AC-4.1 (Бездіяльність):**
- Given сесія без запитів понад 30 хвилин,
- When адмін надсилає запит,
- Then повертається `401` з кодом `admin.session_expired`.

**AC-4.2 (Абсолютний строк):**
- Given сесія старша за 12 годин, навіть з постійною активністю,
- When адмін надсилає запит,
- Then повертається `401` з кодом `admin.session_expired`.

**AC-4.3 (Без CSRF-токена):**
- Given активна сесія,
- When надходить запит, що змінює дані, без CSRF-токена або з невалідним,
- Then повертається `403` з кодом `admin.csrf_invalid`.

**AC-4.4 (Вихід):**
- Given активна сесія,
- When адмін виходить,
- Then сесія видаляється на сервері, і запит з тим самим cookie повертає `401`.

**AC-4.5 (Чужий домен):**
- Given запит надходить з origin, відмінного від домену адмінки,
- When браузер виконує preflight,
- Then CORS-заголовки, які дозволяють запит, не повертаються.

## US-ADM-5 — Права
Як власник проєкту, я хочу, щоб кожен адмін мав доступ лише до своєї зони.

**AC-5.1 (Бракує права):**
- Given адмін лише з роллю `translator`,
- When він викликає операцію модерації,
- Then повертається `403` з кодом `admin.forbidden`.

**AC-5.2 (Кілька ролей):**
- Given адмін з ролями `moderator` і `translator`,
- When він викликає операції модерації й перекладів,
- Then обидві виконуються.

**AC-5.3 (Операція без x-permission):**
- Given адмін-контракт,
- When виконується тест контракту,
- Then він падає, якщо хоча б одна операція не має `x-permission`.
