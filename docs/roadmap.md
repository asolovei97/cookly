# Роадмап

Порядок розробки трьох застосунків. Робота йде **вертикальними зрізами**: бекенд випереджає клієнтів на 1–2 пункти, а адмінка й мобільний застосунок підхоплюють той самий зріз.

На кожен пункт складається план у `plans/<nn>-<пункт>/`: `index.md` (рішення) і `user-stories.md` (юзер-сторі з критеріями приймання Given / When / Then). Кожен AC покривається тестом `TestAC_<US>_<N>_...`.

## Бекенд

Правило еволюції API, `oasdiff`, мінімальна версія застосунку. **Спостережуваність**: структуровані логи з `request_id`, відновлення після panic, `/metrics`, трасування (OpenTelemetry), відправка помилок у крашлітику; локальний профіль Compose з Grafana-стеком |
